# The goal, as it stands on 2026-10-02

You are continuing the port of Mission Planner (C#, https://github.com/ArduPilot/MissionPlanner) to Rust
(`crates/`, a gpui application: `target/debug/planner`). The owner is Buzz; he is the oracle on
look and feel and on scope.

## The four goals (PLAN.md §1.1)

1. **File-complete port** - every one of the 3,678 `.cs` files in a terminal ledger state
   (`ledger/ledger.csv`: `tested`/`ported` with evidence, or `dropped` with the owner's reason);
   `cargo xtask ledger check` exits 0.
2. **Extreme performance** - the numbers in PLAN.md §8, measured, not claimed.
3. **Multi-platform** - Linux, Windows (the tiny10 VM) and macOS from one `cargo build`.
4. **GPU visuals** - map, HUD, charts and overlays composited on the GPU.

## How the work is done (the memory under `.claude/memory/` is the full set)

- Port from the `.cs`: read it, cite it (`// C#: File.cs:lines`), never recall it. Nothing that
  is not in the C# is in scope - ask instead. A file or function nobody calls is recorded out of
  scope, not ported.
- Match Mission Planner's layout from the `.resx`; drop-downs are deferred and anchored; the
  flight screen's mode buttons stay (the owner's ruling). No message box for an error the main
  window can show as state or on the status line.
- Every change ships with a test that fails if it stops working, on the path the product takes:
  unit tests, and a `tests/gui/*.gui` script run headless (`tools/gui-headless.sh <name>`), with
  SITL where the screen needs a vehicle (`tools/sitl/start-sitl.sh`).
- Verify before committing: clippy as its own command, the tests read, then one commit per
  finished item. A commit is never an exit condition - chain to the next item.
- One cargo build at a time, under `flock <scratchpad>/build.lock`; never a release build with
  the VM up; never save, pause or snapshot the VM; VM work goes through `tools/win10/vm-run.sh`.
- Up to six Opus subagents may write code (the owner, 2026-10-02): a worktree each, disjoint
  files named in the brief, the shared target directory through the build lock, never a window,
  never a commit. The coordinator integrates, verifies, records (ledger, coverage, matrix) and
  commits.
- Record each finished item in `ledger/ledger.csv`, `docs/coverage/` (regenerated by the
  `update_report` tests) and the matrix; write every divergence from the C# at its site.
